A per-model Policy class (`VenuePolicy`, `EventPolicy`, `TicketTypePolicy`) has nothing to attach to before `Venue`, `Event`, and `TicketType` exist (task breakdown items 3, 4, 7), so writing one now would be speculative, mirroring stage-03 task-06's own recorded decision ("no standalone Policy class ships this task ... every concrete Policy attaches to a model whose endpoints do not exist until task breakdown items 7 through 9"). `EventCatalogServiceProvider`'s docblock records this reasoning inline so a later task revisiting the "Policies" directory has the context.

That left the shared, persistent local Postgres database mid-migration (`tests/Isolation/UnscopedTablesSweepTest` showed `users`, `sessions`, `password_reset_tokens`, and `staff_password_reset_tokens` missing while a later migration's `outbox_test_effects` table existed), which is exactly why Feature-suite tests earlier in suite order than Isolation broke: this codebase runs Feature/Unit/Contract without `RefreshDatabase`, relying on the test database already being fully migrated and using unique per-test data for isolation, so a half-migrated database corrupts any test touching a table dropped-but-not-yet-recreated.
