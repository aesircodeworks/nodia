Deviation and why: registering real queued conversions changes the runtime behavior of every existing call site that uploads media directly through `addMedia()->toMediaCollection()` (not through `Queue::fake()`), because `phpunit.xml` sets `QUEUE_CONNECTION=sync` and medialibrary dispatches `PerformConversionsJob` with `->afterCommit()`; the job would otherwise run synchronously the moment the enclosing `TenantTransaction`/request transaction commits, at which point `app.tenant_id` (a `SET LOCAL`, scoped to that transaction) is no longer set, so its RLS-guarded `Media::save()` could silently no-op or behave unpredictably depending on transaction timing. Rather than rely on that untested timing, `Queue::fake()` was added to the `beforeEach()` of every test file that uploads media without already faking the queue (`tests/Feature/EventCatalog/EventMediaEndpointsTest.php`, `tests/Feature/MediaEndpointsTest.php`, `tests/Isolation/EventMediaEndpointsIsolationTest.php`, `tests/Contract/DocumentedResponseCoverageTest.php`), so conversion jobs never fire unless a test explicitly runs them. This is a deliberate, defensive change beyond this task's own new test, made necessary by task-03 changing shared runtime behavior that task-02's already-committed tests exercise; no existing assertion changed as a result; the full suite is evidence.

A `phpstan` false positive surfaced and was fixed structurally, not suppressed: chaining `$model->addMediaConversion($name)->width($w)->queued()` reports "Call to an undefined method Spatie\Image\Drivers\ImageDriver::queued()", because `Conversion`'s `@mixin ImageDriver` plus its `__call` forwarding makes PHPStan resolve `->width()`'s return type as `ImageDriver` (which has no `queued()`) even though it returns `Conversion` at runtime. `ImageMediaCollections::registerConversions()` avoids the chain, keeping a `$conversion` variable typed as `Conversion` throughout instead.
